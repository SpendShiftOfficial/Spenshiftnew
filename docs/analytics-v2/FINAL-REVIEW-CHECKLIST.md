The development candidate is source-locked. No production changes or data collection are authorised. ## First-party-only consent and protection
- Separate new basic-statistics choice and existing optional first-party audit/report counts. Existing cookie choices block new basic collection unless explicitly transitioned. Valid older first-party consent may be honoured within its original scope; new optional choices never create a legacy vendor grant. All-statistics opt-out withdraws both categories. No visitor option or environment flag re-enables Google Analytics, Clarity, Meta or TikTok.
- Basic opt-out and independent privacy mode preserved. Vendor loader components are inert, event-forwarding functions are no-ops and global CSP denies remote scripts/frames/connect requests. Owner authentication retains a narrowly scoped Supabase connection exception. No third-party forwarding or server-side conversion pings introduced.
- No expanded financial-answer measurement, unique IDs, private paid-stage/report expansion or opt-choice counts. Basic requests omit credentials and referrer; hosting/security may process metadata. Counts are observations, not unique people or matched conversions.

## Browser storage isolation — mitigated in candidate, cutover review required
- Existing free drafts and completed answers use origin-shared localStorage or sessionStorage. Previously loaded third-party JS could potentially access these stores on the same origin. There is no established evidence of disclosure.
- Removal of all vendor execution paths and site-wide CSP address this risk in newly loaded candidate documents without deleting drafts or changing how the product works. Previously opened old pages, browser extensions, XSS and other same-origin code are not eliminated by this design. No claims of full storage isolation or retrospective deletion.
- Plan an authorised tracker-free cutover and first-party-only rollback. Do not return to vendor-enabled builds or add providers unless separate origin isolation and legal/security review are complete. Review old vendor data/cookies and account terms separately.

- Source lock false; hosted owner path unavailable until separately reviewed release. The production page requires an exact project URL and a dedicated Supabase publishable key, never the service-role key.
- Pre-provision an allowlisted owner account and verified TOTP factor. Browser auth state memory-only, no auto-refresh, twelve-minute UI expiry; server checks authenticated user, MFA assurance, recent token and live session. No customer account changes or signup flow.
- Real Supabase Auth provisioning, MFA enrollment, session expiry/revocation, provider security configuration and owner access must be verified on approved isolated infrastructure before activation. Unit/server authorization tests do not substitute for provider login. No production account created.

## Refined traffic-source classification (26 November 2026)
Approved static UTM source labels (including Instagram/IG, Facebook/FB, TikTok/TT and selected other public platform labels) are mapped to existing broad categories. On an external or unknown-referrer entry, a single valid allowlisted UTM source takes precedence over the referrer classification; otherwise use the broad referrer category or direct/unknown. Same-origin referrers are never converted into new external arrivals by a tag. Duplicate, oversized or unapproved labels are ignored. Only the fixed category is transmitted; no raw tag, full URL, click ID or visitor identifier is recorded. Source labels are declared marketing hints, not verified referral or causal attribution. Campaign labels remain the existing finite catalogue; no new stored field or database migration.

## Australian audience measurement — requested 26 November 2026, pending legal approval
Purpose: assess whether recorded website arrivals reach the Australian market. For validated site_entry events only, the production ingestion route uses Vercel's x-vercel-ip-country header (provider estimates country from public IP), reduces an assigned ISO code to australia, outside_australia or unknown, and passes only that bucket to the aggregate RPC. Missing, malformed, reserved/unassigned or ambiguous values become unknown. No client geo field, precise location permission, external lookup, new identifier, raw IP, original country code, city, region, postcode, coordinates or cross-event linkage. Necessary hosting/security infrastructure may separately process request metadata. Browser payload and consent gate remain unchanged. The daily market marginal is separate from source/device/campaign and other dimensions and follows the 180-day retention. Dashboard shares include unknown in the denominator; incomplete coverage or positive cells below ten suppress the distribution. Not proof of Australian citizenship, residence or qualified unique people; VPNs, proxies and spoofable/incorrect metadata can affect classification. Verify actual Vercel production header behavior and legal basis before activation. No country-based access restrictions or individual targeting.

**Notice:** the concise in-flow disclosure, two equal optional action buttons (accept optional and reject optional), and prominent Privacy settings control must be in the visible viewport across two animation frames before v2 events. Hidden, offscreen, occluded or prerendered pages do not satisfy the initial gate. **Withdrawal:** shared document-wide fail-closed guard covers v2 and original optional audit/report sends. Validate the stored schema, reject malformed values, verify writes (including conservative legacy downgrade) by read-back, and show failure instead of success. Failed saves stop both categories in the affected document, with a best-effort non-identifying per-tab sessionStorage marker surviving reload where it can be stored. Retry verified saving to persist choices; optional choice after failure keeps basic off unless explicitly enabled under the active notice. If both storage mechanisms fail, the in-memory guard stops new sends in the current document, but it cannot ensure other tabs, later documents or devices honour an unsaved choice. Already dispatched requests and aggregate counts are not retroactively undone. An explicit all-off action may repair a malformed stored choice without touching the audit draft. Successful persisted choices propagate through storage on the same origin where supported.
