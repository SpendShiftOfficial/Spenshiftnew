# Purchase attribution: final bounded review candidate — NOT LIVE

## Purpose and scope
Tell which declared source, paid campaign and approved creative leads to confirmed paid orders. Existing basic statistics, Stripe payment creation, webhook, report delivery, cookie decisions, pricing and product remain unchanged. No pixels, CAPI or extra infrastructure. No code or SQL deployment until specific approval.

## Technical and privacy decision
- Basic stats after rejection continue exactly as today. Purchase-linked marketing labels are a different purpose: require a newly disclosed affirmative optional-cookie choice, a verified existing basic permission, and a 204 acknowledgement from the existing site-entry measurement endpoint. Reject, ignore, prior restrictive/old grants without new disclosure, storage failure, excluded IP at landing, unknown or expired labels remain unattributed. No new third-party requests. Existing returning browser choice can be revisited in settings; do not force old grants to accept new processing.
- Finite approved source codes; paid campaign meta_founder_v1 only for facebook/instagram with utm_medium=paid_social; creative_01 to creative_08 or none_or_unknown. No raw URL, referrer, click ID, ad ID, financial answers, email, IP or visitor ID in new mapping. No new marketing metadata sent to Stripe. Cookie notice candidate adds a concise disclosure only when authorized. Existing privacy/cookie policies remain live unchanged while off. 
- Same-tab sessionStorage holds labels and local timestamp for max two hours. A new public document resets the context; the audit and results retain it across full document navigations because the website uses Referrer-Policy: no-referrer. A direct tagged audit/results entry clears prior context. This conservative same-tab association can miss or misattribute unusual navigation; it is not a unique visitor or exact journey. No cross-device matching; localStorage retains only versioned permission. Withdrawal clears context, and a retry of an unpaid checkout without permission removes its stored context where possible. After checkout opened, a mapping can persist until abandonment expiry or confirmed-order retention; already-processed observations are not retroactively erased. Users can contact support for privacy requests. No claim of anonymous purchase-level linkage; server holds a restricted SHA-256 hash of an existing Stripe Checkout ID, allowing association with an existing paid order, so treat it as potentially identifiable.
- Checkout idempotency key and Stripe metadata remain exactly as before. An auxiliary first-party mapping write happens after Stripe returns a session, only after gate, exact origin and validated labels; failure never blocks checkout. The existing verified, unique paid-order record is the numerator, joined by hash on read. No extra webhook counter, double-count or historical backfill. Counts are gross paid orders before refunds, reconciled to Stripe; include test purchases in operational totals. Missing attribution is explicit. No exact causality, per-ad conversion rates, ad optimisation or full campaign denominator; Meta's per-ad spend/clicks/LPVs remain separate. Labels are declared, client-supplied and could be spoofed.
- Proposed retention: abandon mapping after 48h, retain confirmed linkage up to 180 days, prune on existing authenticated cron even after collection off if schema ready. No new data in Stripe. Exact owner-only purchase counts by approved group may be small; **requires explicit legal approval of showing small paid-order groups**; existing anonymous dashboard suppression stays unchanged. No report-level identifiers returned. Scope is payment-confirmed aggregate reporting, not user profiles.
- Home rule excludes existing analytics endpoints. Site-entry acknowledgement is required to capture context, so fresh home-network landings blocked by that rule cannot get attribution. Genuine purchases from home still count in Stripe; an already captured context from another network can carry into checkout. Test purchases should be noted separately.
